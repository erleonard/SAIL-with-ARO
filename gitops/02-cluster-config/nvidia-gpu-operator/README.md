# NVIDIA GPU Operator

The NVIDIA GPU Operator is a Kubernetes operator that automates the management of NVIDIA GPU resources in OpenShift Container Platform. It handles the installation, configuration, and monitoring of NVIDIA GPU drivers, device plugins, and related components.

## Layout

This component is deployed as a single bundle Application, generated by the
`cluster-config` ApplicationSet from the descriptor in
`overlays/<environment>/appset-config.yaml`.

```text
nvidia-gpu-operator/
├── operator/base/                  # Namespace, OperatorGroup, Subscription
├── instance/
│   └── base/                       # ClusterPolicy instance configuration
├── instance/overlays/
│   ├── prod/                       # Production-specific instance configuration
│   └── non-prod/                   # Non-production instance configuration
└── overlays/<environment>/         # Bundle entrypoint + appset-config.yaml
```

The operator and its instance belong to one Application on purpose. Argo CD
sync waves order resources within an Application, but they do not order
separate Applications generated by an ApplicationSet, so keeping the pair
together is what makes the install sequence expressible.

## Configuration

The NVIDIA GPU Operator is configured with the following settings:

- **Operator**: nvidia-gpu-operator
- **Channel**: stable
- **Source**: nvidia-operators
- **Source Namespace**: openshift-marketplace
- **Installation Mode**: Dedicated namespace with OperatorGroup

## Current Configuration

The bundle currently deploys both the operator and the ClusterPolicy instance. The instance
configuration is provided in `instance/base/clusterpolicy.yaml` and is included in
the bundle by default.

The operator will be automatically discovered and deployed by the cluster-config
ApplicationSet when GitOps bootstrap is applied to an environment.

### Intended resource ordering

OLM installs the operator asynchronously, so the instance resources must wait
for CRDs that do not exist when the Application first syncs. Order them inside
the bundle with `argocd.argoproj.io/sync-wave` annotations:

| Wave | Resources | Purpose |
| ---: | --- | --- |
| `-30` | Namespace, OperatorGroup, Subscription | Request OLM operator installation |
| `-20` | Sync hook Job | Wait for the GPU Operator CRDs |
| `-10` | ClusterPolicy instance | Configure the operator and request the operand |

The custom resources should also carry
`argocd.argoproj.io/sync-options: SkipDryRunOnMissingResource=true`, because
their CRDs are created asynchronously by OLM and operator reconciliation.

## Instance Customization

To customize the ClusterPolicy instance configuration for specific environments, modify
the overlays in the instance directory:

```text
instance/
├── base/                           # Base ClusterPolicy instance configuration
└── overlays/<environment>/         # Environment-specific customizations
```

Then reference the environment-specific instance in the bundle:

```yaml
resources:
  - ../../operator/base
  - ../../instance/base             # Base instance configuration
  # - ../../instance/overlays/<environment>  # Environment-specific overlays (optional)
```

## GPU Node Requirements

To use the NVIDIA GPU Operator, nodes must have NVIDIA GPUs and be labeled appropriately.
The default configuration expects GPU nodes to have the following label:

```yaml
node-role.kubernetes.io/gpu: ""
```

Apply this label to nodes that should run GPU workloads:

```bash
oc label nodes <gpu-node-name> node-role.kubernetes.io/gpu=""
```

## Components Managed

The ClusterPolicy instance configures the following NVIDIA GPU Operator components:

- **Driver**: NVIDIA driver management
- **Device Plugin**: GPU device plugin for Kubernetes
- **DCGM Exporter**: NVIDIA GPU metrics exporter
- **GPU Feature Discovery**: GPU node labeling and discovery
- **MIG Manager**: Multi-Instance GPU (MIG) management
- **Fluent Bit**: GPU logging configuration

## Validation

After deployment, verify the installation by checking that all components are running:

```bash
# Check ClusterPolicy status
oc get clusterpolicy gpu-cluster-policy -o yaml

# Check GPU node availability
oc get nodes -l accelerator=nvidia-tesla-v100

# Check GPU device plugin status
oc get pods -n nvidia-gpu-operator | grep device-plugin
```

## Troubleshooting

If the ClusterPolicy fails to initialize, check the operator logs:

```bash
oc logs -n nvidia-gpu-operator deployment/nvidia-gpu-operator-operator
```

For detailed GPU operator troubleshooting, refer to the [NVIDIA GPU Operator documentation](https://docs.nvidia.com/datacenter/cloud-native/gpu-operator/).
